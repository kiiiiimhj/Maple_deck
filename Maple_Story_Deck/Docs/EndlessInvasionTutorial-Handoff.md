전체 콘텐츠를 하나의 부모 아래 묶어 동일 비율로 축소하세요. 화면 크기에 따라 그림과 화살표를 각각 따로 이동·확대하면 끝점이 어긋납니다. 스프라이트는 흰색 틴트와 원본 알파를 유지하세요.

## 6. 참고할 기존 도토리 튜토리얼

현재 코드에서 확인한 참고 메서드:

- `AcornGuideLabels()` — 언어별 문구
- `InitializeAcornGuide()` — 이벤트 연결·리소스 미리 받기
- `FitAcornGuide()` — 전체 콘텐츠 비율 맞춤
- `OpenAcornGuide()` — 초기화 후 1번 노출
- `RevealAcornGuideStage()` — 그림과 도착 방향 화살표를 함께 노출
- `TickAcornGuide()` — 시간에 따른 단계 노출·페이드
- `CloseAcornGuide()` — 화면 탭으로 닫기

이 가이드는 **한 화면에 그림 3컷을 순서대로 보여주는 방식**입니다. 현재 구현은 0초에 1번, 약 0.65초에 2번, 약 1.3초에 3번을 노출합니다. 각 그림은 약 0.15초 동안 페이드되고, 화살표는 도착할 그림과 함께 나타납니다. 배경을 어둡게 하고 화면을 누르면 닫습니다.

새 침식 안내에 이 구조를 재사용하되, 도토리 교환소의 기존 코드와 화면 자체는 변경하지 마세요. 기존 가이드의 사용처·닫기·구매 창 상태도 유지해야 합니다.

## 7. 침식 연결 시 반드시 보존할 최신 코드

침식 본체는 `G:/Maple_Story_Deck/RootDesk/MyDesk/Effects/EndlessBurstLogic.mlua` 입니다. 이 문서 작성 직전에 현재 작업 파일을 읽어 확인했습니다. **이전 대화의 최초 구현과 현재 코드는 다릅니다.** 실제 작업 직전에 다시 읽으세요.

현재 코드에는 클로드가 이미 추가한 내용이 있습니다.

- `FirstSurgeDelay = 5`: 클리어 배너·도전 토스트 뒤 첫 침식 대기
- `BurstSeconds = 20`, `KillsPerBurst = 100`
- `Phase=1`: 첫 침식 전 대기, 이때 침식 HUD·테두리는 숨김
- `Phase=2`: 침식 발동·연출
- `Phase=3`: 침식 연출 종료 뒤 처치 수 집계, 100마리 도달 시 다음 침식
- 강인·광폭·질주·범람·맹공·저주의 단계별 수치와 실제 계산 연결
- 1단계 효과 1개, 2단계부터 5단계까지 2개, 6단계부터 3개를 새로 추첨
- `RollModifiers()`, `GetModifierValue()`, `GetModifierCount()` 및 각 전투 계산 함수
- 광폭은 현재 **퍼센트가 아닌 공격력 고정 가산**으로 변경돼 있음

과거 문서에 있던 “단계마다 체력 +20%, 공격력 +10%” 고정 구현으로 되돌리지 마세요. 튜토리얼 작업을 이유로 현재 효과 계산·추첨·침식 주기를 재구현할 필요가 없습니다.

노출 시점은 **첫 침식이 실제로 발동하기 전**입니다. 클리어 배너·도전 토스트·침식 충격파가 튜토리얼과 겹치지 않도록 현재 `TickServer()`의 대기 흐름과 `StartInvasionWave()` 연결을 확인하세요. 안내를 읽는 도중 서버에서 첫 침식이 먼저 시작되면 안 됩니다.

기존 게임의 일시정지·튜토리얼 처리 방식을 확인해 사용하고, 닫기 후 침식이 정확히 한 번 이어지도록 연결하세요. 다른 팝업이 소유한 일시정지를 잘못 해제하거나 매 프레임 안내가 다시 열리지 않도록 해야 합니다.

**미확정 사항:** 계정 최초 1회만 보여줄지, 매 런의 첫 침식 전에 보여줄지는 사용자가 아직 정하지 않았습니다. 기존 노출 기록 구조를 먼저 확인하고 이 부분은 구현 시 확인하세요. 계정 최초 1회라는 정책을 임의로 확정하지 마세요.

## 8. 작업 보존과 검증

문서 작성 시 로컬 브랜치는 `codex/endless-rupture-burst`이며, 현재 커밋되지 않은 클로드 변경이 있습니다. 기존 변경을 보존한 상태에서 최신 저장소·작업 파일을 확인하고 필요한 부분만 추가하세요.

프로젝트의 `AGENTS.md` 및 관련 지침을 읽고, `.ui`는 UIBuilder로 편집하세요. `.codeblock`은 직접 수정하지 않습니다. UI 텍스트는 기존 모바일 대응을 위해 `TextGUIRendererComponent` 계열을 사용하세요.

그림·화살표 제작 작업은 게임 코드·UI·맵·모델 471개 파일의 해시가 작업 전후 동일함을 확인했습니다. 이는 **이미지 작업이 기존 코드를 바꾸지 않았다는 확인**입니다. 아직 침식 튜토리얼 런타임 검증을 끝냈다는 의미는 아닙니다.

구현 후 확인할 항목:

- 첫 침식 전 올바른 시점에 안내가 열리는지
- 안내 중 전투·침식 타이머가 먼저 진행되지 않는지
- 1번 → 위쪽 화살표와 2번 → 아래쪽 화살표와 3번의 노출 흐름
- 닫기 후 첫 침식이 한 번만 시작되는지
- 화면 비율 변경 시 그림·화살표·캡션 정렬이 유지되는지
- PC 입력과 모바일 터치에서 닫기가 되는지
- 새 런·사망·맵 이동·안전지대·타이틀 복귀 시 상태가 남지 않는지
- 현재 여섯 침식 효과와 100마리 집계가 그대로 동작하는지
- 도토리 교환소 튜토리얼이 계속 정상 동작하는지
- Maker 빌드·런타임 로그와 실제 화면으로 검증했는지

## 9. 전달용 요청문

> 이 인수서를 기준으로 침식 튜토리얼을 구현해 주세요. 최신 로컬 파일과 클로드가 이미 수정한 침식 계산을 먼저 확인하고 보존해 주세요. 첫 침식 전에 도토리 교환소 가이드처럼 한 화면의 그림 3컷이 순서대로 나타나는 안내를 연결해 주세요. 이미지 3장과 V4 화살표 2개는 이미 내 리소스에 등록됐으니 이 문서의 RUID와 최종 시안 배치를 그대로 사용해 주세요. 화살표를 새로 그리거나 과거 버전으로 바꾸지 말아 주세요. 튜토리얼은 아직 게임에 연결되지 않았습니다. 노출 기록 주기는 기존 구조를 확인한 뒤 정하고, 구현 후 실제 메이커에서 흐름과 정렬을 검증해 주세요.
